## Curse Catcher — Critical CVEs

### Fortinet (FortiMail, FortiAnalyzer/FortiManager, FortiOS)

- **[CVE-2026-126147: FortiMail path traversal (CVSS 9.8)](https://nvd.nist.gov/vuln/detail/CVE-2026-126147)** _(Published Nov 11)_ — Unauthenticated attackers can run code with crafted requests on FortiMail 7.2 (all versions), 7.4.0-7.4.8, 7.6.0-7.6.6 and 8.0.0-8.0.1. No known exploitation yet, but Fortinet edge devices have a long history of mass exploitation soon after disclosure, so patch fast and keep the admin interface off the internet.  
  [FortiGuard FG-IR-26-199](https://fortiguard.fortinet.com/psirt/FG-IR-26-199)
- **[CVE-2026-126148: FortiMail OS command injection over HA (CVSS 9.8)](https://nvd.nist.gov/vuln/detail/CVE-2026-126148)** _(Published Nov 11)_ — Unauthenticated code execution through crafted HA join-request packets on FortiMail 7.6.0-7.6.6 and 8.0.0-8.0.1. Make sure HA ports are reachable only from the cluster peers.  
  [FortiGuard FG-IR-26-200](https://fortiguard.fortinet.com/psirt/FG-IR-26-200)
- **[CVE-2026-126263: FortiMail SQL injection (CVSS 9.8)](https://nvd.nist.gov/vuln/detail/CVE-2026-126263)** _(Published Nov 11)_ — Lets an authenticated attacker run code or commands on FortiMail 7.4.0-7.4.6, 7.6.0-7.6.4 and 8.0.0-8.0.1. Needs a login, so it is lower priority than the two unauthenticated FortiMail bugs.  
  [FortiGuard FG-IR-26-277](https://fortiguard.fortinet.com/psirt/FG-IR-26-277)
- **[CVE-2026-126170: FortiAnalyzer / FortiManager unauthenticated code execution over HTTP (CVSS 9.8)](https://nvd.nist.gov/vuln/detail/CVE-2026-126170)** _(Published Nov 11)_ — A crafted HTTP request can run code on FortiAnalyzer and FortiManager 7.6.0-7.6.7 and 8.0.0-8.0.2, including the Cloud editions and FortiAnalyzer-BigData 7.6.0-7.6.2. FortiManager was mass-exploited in 2024 (FortiJump), so restrict the web interface to management networks.  
  [FortiGuard FG-IR-26-219](https://fortiguard.fortinet.com/psirt/FG-IR-26-219)
- **[CVE-2026-126262: FortiAnalyzer / FortiManager SQL injection over OFTP (CVSS 9.8)](https://nvd.nist.gov/vuln/detail/CVE-2026-126262)** _(Published Nov 11)_ — Unauthenticated attackers who can reach the OFTP port (TCP 514, used by managed devices) can run code on 7.2.x, 7.4.x, 7.6.x and 8.0.x builds. Allow that port only from your own FortiGates.  
  [FortiGuard FG-IR-26-276](https://fortiguard.fortinet.com/psirt/FG-IR-26-276)
- **[CVE-2026-126259: FortiOS missing authentication in HA sync (CVSS 9.8)](https://nvd.nist.gov/vuln/detail/CVE-2026-126259)** _(Published Nov 11)_ — Unauthenticated attackers can run commands as super admin with crafted HA packets on FortiOS 7.2.0-7.2.13, 7.4.0-7.4.12, 7.6.0-7.6.7 and 8.0.0. Only setups that use FGSP with standalone-config-sync, or autoscale, are affected.  
  [FortiGuard FG-IR-26-273](https://fortiguard.fortinet.com/psirt/FG-IR-26-273)
- **[CVE-2026-126254: FortiOS BGP numeric truncation (CVSS 9.6)](https://nvd.nist.gov/vuln/detail/CVE-2026-126254)** _(Published Nov 11)_ — A configured iBGP neighbor can send malformed attributes that spread to every connected router (FortiOS 7.2.0-7.2.13, 7.4.0-7.4.12, 7.6.0-7.6.7, 8.0.0-8.0.1). The attacker has to be, or control, a trusted BGP peer.  
  [FortiGuard FG-IR-26-268](https://fortiguard.fortinet.com/psirt/FG-IR-26-268)

### Red Hat Quay (container registry)

- **[CVE-2026-123710: unauthenticated signing-key takeover (CVSS 9.8)](https://nvd.nist.gov/vuln/detail/CVE-2026-123710)** _(Published Nov 11)_ — An anonymous client can install its own signing key through the key-rotation endpoint and then mint tokens that read and write any repository, including private images and tags. That puts the software supply chain at risk: attackers could swap images that get deployed downstream. No known exploitation.  
  [Red Hat](https://access.redhat.com/security/cve/CVE-2026-123710)
- **[CVE-2026-110697: cross-tenant robot token theft via SQL wildcard (CVSS 9.9)](https://nvd.nist.gov/vuln/detail/CVE-2026-110697)** _(Published Nov 11)_ — A namespace name containing an underscore can match other tenants' robot accounts and return their decrypted tokens. This mainly matters on shared, multi-tenant Quay registries. No known exploitation.  
  [Red Hat](https://access.redhat.com/security/cve/CVE-2026-110697)

### Synology DiskStation Manager

- **[CVE-2026-76954: DSM Auth API SQL injection (CVSS 9.8)](https://nvd.nist.gov/vuln/detail/CVE-2026-76954)** _(Published Nov 12)_ — Remote attackers can read or write arbitrary files and crash the NAS. Fixed in DSM 7.2.1-69057-13, 7.2.2-72806-10, 7.3.2-86009-5 and 7.4.1-90080-1. Ransomware crews regularly target NAS boxes exposed to the internet, so update now and don't expose DSM directly.  
  [Synology SA-26:19](https://www.synology.com/en-global/security/advisory/Synology_SA_26_19)

### Zoho ManageEngine

ManageEngine products have been mass-exploited before, and this one holds Microsoft 365 admin rights. No known exploitation.  
  [ManageEngine advisory](https://www.manageengine.com/microsoft-365-management-reporting/CVE-2026-12591.html)

### WordPress plugins

- **[CVE-2026-110959: Descope plugin login bypass (CVSS 9.8)](https://nvd.nist.gov/vuln/detail/CVE-2026-110959)** _(Published Nov 12)_ — Before 1.2.0 the plugin accepts any token, so anyone who knows an account's email can log in as that user, including admins. No known exploitation yet, but it can be scripted at scale and gives full control of the site.  
  [WPScan](https://wpscan.com/vulnerability/8b97f139-cbc3-4913-b69a-a3179f4cc264/)
- **[CVE-2026-124814: Ultimate Addons for Elementor Forms file upload RCE (CVSS 9.8)](https://nvd.nist.gov/vuln/detail/CVE-2026-124814)** _(Published Nov 12)_ — Before 1.0.8, unauthenticated users can upload PHP files and run code. No known exploitation yet, but it can be scripted at scale and gives full control. Bugs like this in WordPress plugins usually get mass-scanned within days.  
  [WPScan](https://wpscan.com/vulnerability/85f2e67b-4c6d-4817-9e4d-ef62a7ddb081/)
- **[CVE-2026-124815: Clockinator Lite unauthenticated SQL injection (CVSS 10.0)](https://nvd.nist.gov/vuln/detail/CVE-2026-124815)** _(Published Nov 12)_ — Before 1.1.0, anyone can delete data from any table and pull password hashes. No known exploitation yet, but it can be scripted at scale and gives full control.  
  [WPScan](https://wpscan.com/vulnerability/a7fe2ca1-ddfe-45fa-93e2-e0959ae29256/)
